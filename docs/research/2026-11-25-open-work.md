# Open work, 2026-11-25: streams and ownership

Everything left after the [viewer review](2026-11-21-viewer-review.md), the [focus review](2026-11-22-focus-review.md) and the [UX council](2026-11-24-ux-council.md), split into five streams that run in parallel worktrees. A coordinator session merges each landed stream into local `main`; nothing is pushed.

## Rules for every stream

- Own worktree and branch, cut from `main`. Before landing: rebase on the latest `main`, then `npm test`, `npx tsc --noEmit` and the browser scenarios (`answers`, `controls`, `place`, `publish`, `live` tests; `SPIKE_URL` at your port), and `node scripts/zoom.mjs follow .. maps/zoom-in-architecture.json --since HEAD`.
- Own dev server port (below); 5180 is taken by another app on this machine. Maps live in the main checkout's gitignored `spike/public/models` and `spike/imports`: copy them into your worktree.
- Every change: a black-box scenario in the browser scripts, before/after screenshots, a review by a model of another family (Codex `gpt-6.2-astra`) before landing. Commit each finished item; no attribution lines; never push.
- Files a stream owns are its own; touching another stream's files is allowed only for a small hook, said in the commit.

## Streams

1. **Endpoints and places** (port 5191). Owns `src/details.ts`, `src/controls/*`, `src/places.ts`, the panel half of `src/main.ts`.
   - Endpoint list in both views: "Endpoints · 67", grouped by resource, method filters, "Unseen · N", each row a jump; reachable from the default view.
   - Search finds endpoints and routes from any view and crosses to Requests; search groups a file shared by many endpoints.
   - Surface on the default view: app cards and panels state their endpoints and entry points; a controller's panel leads with **Serves** (its routes from `marks`).
   - Effect-first endpoint panel: takes, reads and writes, returns (full generic type), called by; numbered steps one expand away.
   - Features meet endpoints: a feature shows its pages, endpoints and their data effects. Welcome counts endpoints, with "See the API".
   - The address restores place and selection (`in=` and `at=` together); switching views keeps the selected request.
2. **Map data** (port 5192). Owns `scripts/map.mjs`, `scripts/graph.mjs`, `scripts/requests.mjs`, `scripts/routes.mjs`, `skills/map-repo`.
   - Transport on boundary links: a `via` on map links (HTTP, JPA, SQL, WebSocket, …), checked, carried into the model, drawn first on the arrow ("HTTP ×10", "JPA → PostgreSQL").
   - Entry points beyond HTTP: scheduled jobs, socket and message handlers, CLI mains, from existing `marks`, as model data the viewer lists (stream 1 shows them).
   - Store arrows tell a mapped relation from measured traffic.
3. **Visual system and layout** (port 5193). Owns `src/render.ts`, `src/layout.ts`, `src/layout.worker.ts`, `index.html` styles, `src/models.ts`, `src/minimap.ts`.
   - Council open items: fill sparse containers (~80% of the body), fit the 1920 overview to the stage, long step names on two lines, supporting types shorter with their own glyph, 44 px touch targets, D22-D26, E29-E31, F32-F34.
   - Connections renamed Coupling and made a layout option.
4. **Problems view** (port 5194). New `src/problems.ts` and its panel section; small hooks elsewhere.
   - Cycles between siblings and dependencies against the grain (a shared model or a store reaching back up into a feature), heaviest couplings: drawn on the map in a warning style and listed in the panel, steppable with `]` `[`.
5. **Change and traces** (port 5195). Owns `scripts/trace.mjs`, `scripts/otlp.mjs`, `scripts/observed.mjs`, `scripts/store.mjs`.
   - "Changed since" overlay: the store keeps the previous upload of a map; the viewer marks what changed since then (new or removed endpoints, crossings, dependencies between components).
   - Traces: page → endpoint from the browser suite (request headers such as `Referer`, enabled in the agent), method-level call trees as an opt-in, and which test made a request where the run allows it.
   - Parked: Node and Python backends. No project with an end-to-end suite on those runtimes is on this machine to prove the agents against.
